# Тестирование CLI (для контрибьюторов)

Команды ниже для **разработки репозитория**, не для пользователей опубликованного пакета.

## Юнит-тесты

```bash
npm run test
```

Проверка типов:

```bash
npx tsc --noEmit
```

## Локальная проверка перед публикацией

```bash
npm run test
npm run build
npm pack
```

**Полная предрелизная проверка** всех комбинаций интерактивного CLI (для каждой — scaffold, затем `npm install` и `npm run build` в сгенерированном приложении).

При текущем наборе промптов (только React; HTTP: Axios, ofetch или Fetch; форматтер: Prettier или Biome) полная **сборочная** матрица — **288** комбинаций (архитектура × `httpClient` × валидация × стили × форматтер × роутер × TanStack Query). Multiselect дополнительных npm-пакетов **не** разворачивается: сейчас они меняют только зависимости в `package.json`, а не генерируемый код, поэтому отдельные install/build на каждое подмножество не гоняются.

```bash
npm run test:cli:matrix
```

Команда долгая и тянет сеть; в **`npm test` не входит**.

Поведение:

- Прогоняет **все** запланированные комбинации, даже если часть падает (не останавливается на первой ошибке).
- В начале **очищает** каталог `.tmp/cli-matrix` (остатки сгенерированных проектов после прерванных запусков), затем создаёт новую рабочую область для текущего прогона. Удаление каждого дерева **ограничено по времени** (~10 с): при блокировке файла (часто нативные `*.node` на Windows) скрипт **не ждёт бесконечно** и идёт дальше, часть каталогов может остаться на диске.
- В консоли — строки `ok` / `FAIL` по каждой комбинации и **итог**: сколько успешно / с ошибкой, время.
- Пишет **JSON Lines** лог: первая строка `{"type":"meta",...}`, далее по строке `{"type":"result",...}` на комбинацию. По умолчанию файл в **`logs/matrix-<runId>.log`** в корне репозитория (каталог `logs/` создаётся при необходимости; с шардом — суффикс `-shard-i-of-n`).
- Код выхода **`1`**, если была хотя бы одна ошибка (удобно для CI); **`0`**, если все прошли.

Флаги:

- `--max=N` — только первые N комбинаций (быстрая проверка).
- `--shard=i/n` — только комбинации с `index % n === i` (параллельные job’ы в CI, например четыре шарда `--shard=0/4` … `--shard=3/4`).
- `--concurrency=k` — до `k` комбинаций параллельно (по умолчанию `1`).
- `--log-file=<path>` — явный путь к JSONL-логу (каталоги создаются при необходимости).
- `--verbose` — полный вывод дочерних процессов.

Пример для GitHub Actions: матрица `shard: [0,1,2,3]` и `npm run test:cli:matrix -- --shard=${{ matrix.shard }}/4`.

## Smoke-проверка CLI

Проверяет, что CLI (из `src/cli.ts`) создаёт проект и что сгенерированное приложение собирается:

```bash
npm run test:cli:smoke
```

Поведение:

- Запуск CLI из `src/cli.ts` (отдельный шаг `tsup` для CLI в этом скрипте не обязателен).
- Временный проект в `.tmp/cli-smoke`.
- Ответы на промпты через фикстуру (`VOSHOD_PROMPT_FIXTURE_JSON`).
- `npm install` и `npm run build` в сгенерированном проекте.
- Удаление временной папки при успехе.

Флаги:

- Оставить проект: `npm run test:cli:smoke -- --keep`
- Имя каталога: `npm run test:cli:smoke -- --name my-smoke-project`

## Интерактивный playground

Полностью интерактивный запуск:

```bash
npm run test:cli:play
```

То же, затем **install + build**:

```bash
npm run test:cli:play:full
```

Рабочая область: `.tmp/cli-playground/<timestamp>`. После запуска скрипт спрашивает, удалить ли каталог.

## Фикстуры промптов

Для неинтерактивного режима можно задать `VOSHOD_PROMPT_FIXTURE_JSON` (JSON-массив ответов в порядке полей в `PromptService.askOptions`).

Единый способ собрать массив из типизированных опций — `src/test-support/promptFixture.ts` (`cliOptionsToInjectedFixtureJson`). Его используют `scripts/cli-smoke.ts` и `scripts/cli-combination-matrix.ts`, чтобы порядок не разъезжался с промптами.

Подробнее по-английски: [testing.md](./testing.md).
